# Views

A view composes data sources, components, bindings, actions, and layout into a screen. Read the
envelope and only the supporting syntax used by the requested interaction.

| Need | Read |
| --- | --- |
| Screen envelope, filters and query actions | [View](view.md) |
| Layout tree, splits, stacks and tabs | [Layout](layout.md) |
| Menu groups, hidden destinations and contextual links | [Navigation](navigation.md) |
| Record, board, file and provider UI | [Components](components/index.md) |
| Table, record, projection, aggregation and provider queries | [Data sources](data-sources/index.md) |
| State, routes, values, refresh and compute | [Bindings](bindings/index.md) |
| State changes, navigation, provider actions, refresh | [Actions](actions/index.md) |
| Workspace tables, files, workflows and agents | [Workspace provider](providers/workspace.md) |
| Live orchestrator resources | [Orchestrator provider](providers/orchestrator.md) |
| Role-specific screen access | [View access](../security/view-access.md) |
| Shareable state, routes and destinations | [Sharing](../security/sharing.md) |

For choosing the screen composition, see [App design](../../design/app-design.md). Query filters
and navigation visibility are presentation decisions; authorization belongs to [App security](../security/index.md).
